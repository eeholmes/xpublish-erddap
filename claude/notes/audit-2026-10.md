## Outcome

EH chose to open **every** finding as an issue: #55–#72, created in the
order to do them, each with its order, dependencies, definition of done and
the smallest model that should manage it (EH works in Opus 5.5 and wants to
hand suitable tasks to Sonnet or Haiku). Blocking the first release: #56 (one
failing store breaks the server-wide root), #57 (a value off an axis is
snapped to the end, 200), #58 (a raw `+` in a time offset is dropped, 200,
wrong row). Comments with new evidence went on #2, #6 and #10.

Corrections the audit made to earlier notes:

- "400 where ERDDAP says 404 for an out-of-range value" was only ever true for
  an **index**; a value was never refused (#57).
- Finding 4 first proposed 400 for impossible dates and `last+1`. ERDDAP's
  documentation says otherwise: dates roll over (`2019-01-32` is 2019-02-01)
  and `last+n` is valid when `+` is encoded (#58).

## How it was run

Five audit agents in parallel (client compatibility; griddap gaps + parity;
correctness; hosting + performance; release + code health), then three for
#52 (plotdap + rerddap vignette; erddapy guides; ERDDAP's griddap
documentation + CoastWatch tutorial 3). Each ran its own server copy of
`tests/server.py` on its own port, compared with real ERDDAPs, made no repo
edits, and the lead re-ran every blocking finding before posting.

Things that bit, worth knowing next time:

- A bare `pytest` collects the git-excluded `collaborator-test/` and dies
  (`SystemExit: 1`) until #55 adds `testpaths`. Run `pytest tests`.
- `pytest -p no:cacheprovider` breaks pytest-xprocess: the 16 live-server
  tests error with `'Config' object has no attribute 'cache'`.
- A `--cov` run leaves `.coverage` in the repo (not ignored until #55).
- A scratch server without `max_response_mb` will try to build a whole
  variable: one probe (`.csv?chlor_a`, ~31 GB) was stopped only by
  coastwatch refusing it. Set a limit on any server you start (#63).
- `pkill -f` with a pattern in your own command line kills your own shell
  (happened again).
- netCDF-C's DAP client cannot read Byte variables from coastwatch (e.g.
  `noaacrwdhwDaily` `mask`); use ERDDAP's `.nc` or pydap.
- The hub's R clients are older than CRAN's (rerddap 1.2.1 vs 1.3.0,
  rerddapXtracto 1.2.3 vs 1.2.5); the audit installed the CRAN versions and
  plotdap 1.2.0 into a scratch library. shapely 2.2.0 was installed into
  `~/venvs/xpe` for tutorial 3.

## Checked and found fine (do not redo)

- **No data reads on metadata endpoints** (das, dds, ncml, info, indexes,
  search, advanced search, axis-only csv/nc): 0 reads through a read-refusing
  lazy backend.
- **Constraint grammar identical to coastwatch 2.31:** ISO times in every
  documented form (when `+` is encoded), epoch seconds, `last`, `last-n`,
  `(last-d)`, `[]`, index ranges in either order, strides, descending axes,
  `(0)` on a one-value axis, `var.var[...]`, percent-encoding, graphics
  options ignored on data types, the documentation's own example URLs.
- **Axes and dtypes:** descending axes, `t` as time, one-value time axis, NaN
  in an axis (refused), packing and fill values from netCDF and Zarr v3,
  integer axes, int16/float/bool/datetime data, large-grid size estimates.
- **Clients end to end:** erddapy (griddap_initialize, to_xarray, to_pandas
  csvp/csv/csv0, info/search URLs, search_servers, download_file, the erddapy
  griddap docs page at stride 1, percent-encoded URLs with pandas); rerddap
  1.3.0 (info, griddap nc/csv, ed_search[_adv], ed_datasets, global_search,
  version, depth/zlev/altitude dims, estimate_griddap_size, every griddap
  example in its vignette, identical data to coastwatch); rerddapXtracto
  1.2.5 (rxtracto, rxtracto_3D, rxtractogon); plotdap 1.2.0 (every vignette
  section, on `latitude`/`longitude` data); CoastWatch Python tutorial 3
  (byte-identical to oceanwatch).
- **Hosting:** `has_server_root` on/off as documented, `_xpublish_id`
  stamping, constant per-dataset root cost, thread safety under eviction,
  `--root-path` URLs, `deploy/server.py`'s proxy settings.
- **Release:** sdist/wheel build, `twine check`, `check-manifest`, entry
  point, README examples, `min-deps` really installs the floors.

Sources with nothing griddap-specific left to test: the CeNCOOS ERDDAP
guide and the k-rns data-reuse workshop (tabledap or UI apart from patterns
listed above).
